<Aside>
  Skipper is designed to run inside Kubernetes. You should not run the code natively (e.g., with `go run .`). All changes should be built
  and deployed using the provided scripts.
</Aside>

## Deploying to Kubernetes (Orbstack)

To deploy all the necessary resources to your local Kubernetes cluster:

```bash
deploy
```

This will build and deploy everything in the `deploy/` directory. The script lives at `scripts/deploy.ts` and has many options. For example, to deploy only Skipper:

```bash
deploy --only=skipper
```

Any code changes you make will be picked up when you run `deploy` again. The `deploy` script will automatically build the latest code and update your Kubernetes environment.

See `deploy --help` for available flags.

## Smoke testing with fixture scripts

A unified `fixture` script is provided in the `scripts/` directory to help you quickly smoke test your Skipper deployment. It offers subcommands to verify basic request routing, WebSocket handling, and load balancing against the deployed fixture server.

### fixture request

Sends a simple HTTP request to the fixture function via Skipper's router and prints the response.

```bash
fixture request
```

### fixture websocket

Opens a WebSocket connection to the fixture function via Skipper's router, sends a test message, and prints the echoed response.

```bash
fixture websocket
```

### fixture load-test

Performs a basic load test by sending multiple concurrent requests to the fixture function via Skipper's router. Useful for verifying load balancing and basic performance.

```bash
fixture load-test
```

The `fixture` script is implemented in Node.js and is available as a command in your development shell. It is a quick way to verify that Skipper is routing requests correctly and that the fixture server is functioning as expected.

All `*.local.*` files are ignored by `.gitignore` so you can duplicate and create your own scripts without committing them (e.g., `fixture.local.ts`).

## Cleaning up resources

To clean up all deployed resources and temporary files:

```bash
clean
```

This will:

- Delete all Skipper-related Kubernetes namespaces (development, test, and fixtures).
- Remove metrics server resources.
- Clear temporary files (logs, test artifacts, etc.).

Use this when you want to start fresh or remove all traces of Skipper from your local Kubernetes cluster.
